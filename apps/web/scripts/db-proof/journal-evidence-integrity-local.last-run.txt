Changed in the migration by this proof (syntax only, unambiguous):
  verify_journal_chain_v1: `returns table (... position integer ...)` → `"position" integer`.
  `position` is a PostgreSQL keyword that is not allowed as a function OUT-column name; the file
  failed to apply at all (SQLSTATE 42601 "syntax error at or near position", char 10804). Quoting keeps
  the output column name `position` unchanged for every caller.

Findings against the migration (NOT changed by this proof — author/owner decision):
  F1  T6/T9  service_role cannot execute journal_evidence_guard_bypassed_v1(): EXECUTE is revoked
             from public and never granted to service_role, while the SECURITY INVOKER guard
             triggers call it as the invoking role. Every service_role UPDATE/DELETE on
             journal_entries and audit_logs fails with 42501 "permission denied for function
             journal_evidence_guard_bypassed_v1" — including the one sanctioned erasure bypass.
             Fix: grant execute on function public.journal_evidence_guard_bypassed_v1() to service_role;
  F2  T7b/T7c chain order ≠ verifier order: rows are linked in advisory-lock order, but the head
             lookup and the verifier both order by created_at (= transaction start, or whatever a
             direct PostgREST insert supplies). Interleaved concurrent saves → verifier reports
             prev_mismatch on honest rows; a client-supplied backdated created_at is stored as-is
             and the next insert chains past it (fork). Fix (verified in PASS B): under the lock,
             `new.created_at := greatest(now(), head.created_at + 1 microsecond)` — server-
             authoritative, strictly monotonic per worker; no live insert path supplies created_at.
  F3  T4b    project_id is part of the hash input on INSERT but the evidence guard allows it to
             change (the live RPCs re-attribute projects) → after a legitimate project_id update the
             verifier reports self_mismatch for the row. Decide: drop project_id from the hash
             input (and from the verifier), or make project_id immutable for version-2 rows.
