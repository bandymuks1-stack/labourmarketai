The public summary of the functionality registry: how many processes exist, how many are proven in production, and how the rest stand — per area and per status.
Part of the master set: [MASTER-MAP](LABOURMARKET-MASTER-MAP.md) · [IMPROVEMENT-OPPORTUNITIES](LABOURMARKET-IMPROVEMENT-OPPORTUNITIES.md) · [EXECUTION-ROADMAP](LABOURMARKET-EXECUTION-ROADMAP.md).

Public-safe summary (owner decision 2026-10-21). The per-process registry — every row with its evidence, dependency, role, defects, dormant code and permission details — lives in the owner's PRIVATE registry (Agentai OS Internal Brain, `docs/internal-brain/projects/labourmarket-functionality-registry-v2.md`). This file keeps only the generated counts. Earlier versions of this file in the public history are superseded by that registry.

## Status vocabulary (owner, 2026-10-21)

| Status | Meaning |
|---|---|
| LIVE_PROVEN | Proven in production — a production walk with the synthetic QA cast (`prod-qa-walk.yml`), a recorded human UI proof, or real production use. The evidence is named in the row. |
| IMPLEMENTED_UNVERIFIED | Code exists and is reachable; not proven in production. |
| PARTIAL | Only part of the process works; the row says which part. |
| BROKEN | Does not work. |
| NOT_BUILT | Only in documents, drafts or unmerged PRs. |
| BLOCKED | Built, but unreachable until a named configuration, account or owner decision is in place. |
| DUPLICATE / RETIRED | Kept for traceability, **not counted**: the same process as another row, or code that is retired. |

A green CI run is **never** counted as functional proof: LIVE_PROVEN needs a production walk with the synthetic QA cast, a recorded human UI proof, or real production use, named in the private row.

**One registry, two views.** The private registry is the single functionality registry ordered by the owner on 2026-10-21. After a process changes, its private row is updated with its evidence and the public counts are regenerated with `node .github/scripts/registry-summary.mjs --registry <private file>`; `lib/guards/functional-registry-summary.test.ts` fails CI when the public tables do not add up or when per-process rows reappear here.

## 3. How to keep this summary current

- A production walk that proves or breaks a process updates its PRIVATE row (status + evidence + PR) in the same work as the fix; then the public counts are regenerated (above).
- A capability-register change updates the register snapshot in the MASTER-MAP (guarded).
- Production counts, logs and security proofs stay in the private annex only.
