2 · Worker path READY

First 5 minutes

  1. Sign in at /auth/login → land on /dashboard. A new account is routed through /onboarding (role, name, country) first — expected.
  2. Set trade + skills at /dashboard/profile. Empty = honest "none yet" pillars + "add profession first" prompt.
  3. Open the player card at /dashboard/player-card. Empty = honest zeros + "None yet" for verified skills. Nothing faked.
  4. Write a journal entry at /dashboard/journal. No employer yet = honest "waiting on organization". With one = composer is visible.
  5. Link entry → skill on the entry row. Raises that skill to the work-journal tier on the card automatically.
Healthy screen: the dashboard work card states one clear next action; every empty screen has a message + a button, never a blank panel.

3 · Company path READY

First 5 minutes

  1. Company dashboard /dashboard/company. No company yet → guided to create one at /dashboard/start/company.
  2. Create a need — the "First action" block. Saves a private draft (customer_requests) and says so; not auto-submitted, not billed.
  3. Structure the need's skills, then scout /dashboard/company/scouting?request=<id>.
  4. Shortlist — status buttons persist per-demand to demand_shortlist (your own rows only).
Sparse-data behaviour (all honest, no error): "need not structured yet" · "no matching workers yet" · ranked candidates with why / gaps / confirmed-vs-declared — never a global person score.

While testing on prod, do not create fake shortlist rows or fake needs.

4 · Manager path READY

  1. Inbox /dashboard/inbox. Nothing pending → honest empty state (no fake entries).
  2. Confirm skills on a pending entry → pick which declared skills it proves → submit. Calls the live confirm_entry_and_verify_skills RPC and raises them to the manager-confirmed tier. A real human decision — nothing auto-confirms.
Verified on prod (read-only, 2026-06-12): both confirm_entry_and_verify_skills and review_journal_entry RPCs exist; 2 real manager_confirmed skill rows. The evidence loop is closed.

5 · Matching / scouting / shortlist READY

  • Matching v1 (lib/market/match-v1.ts) — deterministic, evidence-weighted (manager-confirmed > work-journal > self-declared), §19-compliant; tested for sparse / insufficient-data / determinism.
  • Scouting returns a tagged state for every path (not-found / needs-migration / not-structured / no-candidates / ok) — never throws on thin data.
  • Shortlist buttons wire to a server action backed by the owner-scoped demand_shortlist contract.
