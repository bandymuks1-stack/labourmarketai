# G-21 — a Playwright subset in CI, and the rot it immediately found

**Date:** 2026-09-01
**Baseline:** `main = f07a6a94` · tree clean
**Verified:** on the GitHub runner. An earlier local-only verification was
**not** equivalent and is corrected in §3.

---

## 1. What was asked

> Establish a small meaningful actor-specific Playwright CI subset so E2E rot
> becomes visible. **Do not dump the entire suite into CI blindly.**

The master audit records G-21 as `IMPL / P2`: *"CI runs zero Playwright specs —
E2E rot is invisible"*, and notes that browser drift went unnoticed until
2026-09-01. There are **93 specs** and CI ran **none** of them.

## 2. Why not the whole suite

Most specs need an authenticated identity and a test Supabase project. A CI job
that is red for environmental reasons teaches everyone to ignore CI, which is
worse than the gap it was meant to close. So the subset is **secret-free by
construction**: public routes only, no login, no `SUPABASE_TEST_URL`, no
database.

It is also a **separate workflow** rather than a step inside `quality`: the
required gate's cost stays flat, and this check can be watched for stability
before anyone considers making it required (branch protection is an owner
action regardless).

## 3. The subset — 21 tests, grouped by actor

| Actor | Spec |
|---|---|
| visitor / acquisition | `primary-route-live-smoke` (public routes only) |
| locale visitor | `ru-landing-localization` |
| mobile visitor | `landing-mobile-overflow` |
| unauthenticated auth | `auth-field-touch-floor` |

**21 tests, all green on the runner.**

### Corrected after the first CI run — "secret-free" means at RUNTIME

The first version of this subset was 32 tests, verified **locally**, and it
**failed in CI**: 28 passed, 4 failed. The local verification was not
equivalent to CI, because this workstation has `apps/web/.env.local` — so the
locally started server had Supabase credentials and CI's did not. A subset
declared "secret-free" was verified in an environment that was not.

`next build` is env-independent in this repo (`quality.yml` depends on that).
**Serving is not.** Both CI failures were environmental, and neither is a
product defect:

| Failing test | Why it fails without env |
|---|---|
| `mobile-marketing-nav` → "every marketing link is reachable" (×3 widths) | asserts **zero console errors** while walking every marketing link; without Supabase env those pages emit subresource **500s** |
| `primary-route-live-smoke` → "auth-gated routes" | expects `/lt/onboarding` to bounce an anonymous visitor to `/auth/login`; without env the middleware cannot decide a session, so the page renders |

Both are excluded so this job stays a statement about the **product** rather
than about the **runner**. `mobile-marketing-nav` still runs locally and keeps
its mobile-visitor coverage there; `landing-mobile-overflow` carries that actor
in CI.

The `--grep-invert "auth-gated routes"` exclusion fails in the safe direction:
if that describe title changes, the block comes **back in** and the job goes
red — it can never silently drop coverage. And if the pattern ever matched more
than intended, the count floor catches it.

## 4. The two guards are the actual deliverable

A Playwright job that silently runs *fewer* specs than intended is worse than no
job — it reports green while covering nothing. Both ways that happens are
guarded:

1. **Spec allowlist still resolves.** Every named path must exist. A renamed or
   deleted spec fails the run instead of shrinking it.
2. **Executed count is above the floor.** Playwright **exits 0 when everything
   skips**. The JSON report is parsed and the run fails below `MIN_EXPECTED=21`.

Without those, this workflow would itself be an assertion that cannot fail —
the defect class this repo has now hit three times (see §6). The floor is a
ratchet: adding tests is fine, and it must never be lowered to turn a red run
green, because **a dropping count is the rot signal**.

## 5. What the subset found on its first run — 5 failures, both TEST class

Classified before anything was touched. **Neither was a product failure, and no
product code was changed.**

### 5a. `ru-landing-localization` — harness defect, FIXED

The spec asserted five Russian strings on `/ru` immediately after `goto`. Two
of them — `previewLabel` ("Наиболее подходящий человек") and `persistAction`
("Сохранить результат") — render **only** inside `hero-live-demo`'s `continued`
branch, which the visitor reaches by pressing the decision's next-action
button. They are not on first paint and no amount of waiting produces them.

So a **fully and correctly translated** Russian page was raising a localization
alarm, because the harness never performed the interaction its own assertion
depended on.

**Fixed in the spec only:** click `hero-next-action`, assert the player-card
preview appeared, *then* assert the strings. The assertion stays strong — the
strings must still be Russian — rather than being weakened to whatever the
first screen happens to show. **2 passed** after the fix.

### 5b. `pr-i-reality-landing` — 4 failures, NOT fixed, needs a product decision

Three assertions target surfaces that exist **nowhere in the codebase**:

| Asserted | Status in the product |
|---|---|
| `#conversation` | rendered only by `ConversationOsPanel`, which **nothing imports** — orphaned |
| `#partners` | **no such anchor anywhere** |
| `live-product-demo` (testid) | **no such testid anywhere** |

The landing is now `FocusLanding`, composed of `HeroLiveDemo` →
`ProductChainBand` (inside `#how-it-works`) → `MarketProofBand` →
`PlayerCardShowcase` → `TrustBand` (`#trust`) → `FinalCtaBand`. The three
asserted surfaces are not part of it.

**This was deliberately left alone**, and excluded from the CI subset rather
than deleted or rewritten:

- Rewriting the spec to match today's page would erase the last written record
  that those surfaces were ever expected — precisely what the preservation law
  (master audit §Q/§V) exists to prevent.
- It is an open instance of **`docs/ARCHITECTURE.md` §7 question B** — *did we
  make impossible something the architecture previously allowed?* A change can
  pass every test and still fail B. Two of the three surfaces have **no
  implementation at all**, and the third is orphaned code, so this is not a
  cosmetic rename.

**Owner/product question:** were `#conversation`, `#partners` and
`live-product-demo` intentionally dropped in the focus-landing redesign, or
lost? If intentional, the spec should be retired *with that decision recorded*
and `ConversationOsPanel` either re-homed or explicitly parked. If lost, this is
a real regression and the spec found it.

Either way it is a decision, not a cleanup, so nothing was done to it here.

## 6. The pattern worth keeping

Four assertion/verification defects have now been found in three consecutive
slices, and all four would have been read as a statement about the product:

| Slice | Defect | Direction |
|---|---|---|
| G-02 | `result is not null` on a status-string RPC | **vacuous** — could not fail |
| G-04 | unscoped `engagement_contexts = 0` | **over-broad** — false alarm |
| G-21 | assertions on a phase the spec never entered | **unreachable** — false alarm |
| G-21 | "secret-free" subset verified in an environment that had the secrets | **wrong environment** — false pass |

None is fixed by adjusting a number until it goes green. Each was fixed by
finding out *why* — and in three of the four cases the product was correct all
along.

The fourth is the one worth dwelling on, because it was mine and it shipped: a
verification is only worth what its environment is worth. Running the "no
credentials" subset on a machine that has `.env.local` proves nothing about a
runner that does not.

## 7. Reproduce

```bash
pnpm -F web build
pnpm -F web exec next start -p 3000
```

then, against that server:

```bash
E2E_NO_SERVER=1 E2E_BASE_URL=http://127.0.0.1:3000 pnpm -F web exec playwright test tests/e2e/primary-route-live-smoke.spec.ts tests/e2e/ru-landing-localization.spec.ts tests/e2e/landing-mobile-overflow.spec.ts tests/e2e/mobile-marketing-nav.spec.ts tests/e2e/auth-field-touch-floor.spec.ts
```

## 8. What this changes about the master audit

G-21 recorded *"CI runs zero Playwright specs"*. That is now false: a named,
actor-grouped, secret-free subset of **21 tests** runs on every PR and every
push to `main`, with two guards that make a shrinking subset fail loudly.

The gap that remains is the **authenticated** half — the specs that need a
fixture identity and a test Supabase project still run nowhere. That is a
separate job with its own stack, and it is the natural next wagon.
