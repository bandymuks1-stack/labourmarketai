# Phone UX gaps — five paths, 375 and 390 px (2026-11-18)

## Method

Everything ran on a throwaway local stack on one machine, built from `main` at
`08181fa9b` (no production host, project or account was contacted; the
production host names were blackholed in `/etc/hosts` for the run, as the
workflow does). The steps of `.github/workflows/signup-isolated.yml` were
followed in order: the guards (no secrets, no linked project, no env files,
Confirm email off), the hash-pinned non-replayable migration verified and set
aside, `supabase start` with the same excluded services (all migrations replayed
from scratch: 477 migration files = 477 ledger rows), the local-only env export
with the same refusal checks, the two `booking_refuses_closed_need` database
checks (regression and race: all PASS), `pnpm -F web build` with
`NODE_OPTIONS=--max-old-space-size=6144` (the local Supabase URL is inlined),
the app on :3000 in acceptance mode, a local Mailpit on 127.0.0.1:465/54334 and
the mail-enabled instance on :3001, then the workflow's Playwright invocation
over its whole `SPEC` list with `--reporter=list --trace=off`. The phone walk
then drove the same stack in Chromium at 375 × 667 and 390 × 844 (touch,
`isMobile`, a phone user agent, device scale 1) through the journeys the
isolated specs perform, with new synthetic accounts for each path and width,
measuring at every screen: sideways scroll (body width past the screen),
controls outside the screen, controls smaller than 44 px, clipped text, fixed or
sticky bars over controls, and the actions on the first screen.

**Deviations from CI.** (1) Root Docker host, `SUPABASE_INTERNAL_IMAGE_REGISTRY=docker.io`
instead of `ghcr.io`. (2) Node 22.23.4 instead of Node 20. (3) `pnpm install
--frozen-lockfile --prefer-offline --filter=!mobile`. (4) No `playwright
install`: the repo's Playwright 1.62.1 expects Chromium build 1234; the
pre-installed build 1243 was mapped to that name with symlinks
(`PLAYWRIGHT_BROWSERS_PATH`). A first suite run before that mapping launched no
browser at all (every test failed at `browserType.launch`) and was discarded;
the stack was not reset in between (it left one auth user). (5) Keys were kept
in a mode-600 scratch file, not masked through `::add-mask::`, and deleted at
the end. (6) `CI=true` was exported to match a runner.

**Not covered.** The workflow's app-rollback compatibility step (pre-#2887
build on :3002 and `job-fit-main-compat-isolated.spec.ts`) and the
experience-integration artifact upload. Messages, bookings and applying were not
re-walked (the phone spec covers them and passed). The walk did not log in a
second person to accept invitations. Pages that scroll inside the app shell
(`/dashboard`) were measured on their first screen only. Lithuanian and other
locales were not walked (English only). Screenshots stay outside the repository.

## Reading the tables

Severity: **blocks** (the person cannot finish the task), **slows** (more taps,
scrolling or precision than needed), **unclear** (the next action is hidden,
competing or contradicts the page). Evidence: **observed** = seen in the
browser on this stack at both widths unless a width is named; **code read** =
the cause or the fix location comes from reading the code, not from the walk.
Tap counts include typing into a field as one action. Every fix is in an
existing file on `main`; none adds helper text (decision 0032).
