# ADR 0009 — Multilingual Answer Engine (publishing architecture)

**Status:** Accepted (Wave 0 architecture; publishing waves owner-gated) ·
**Date:** 2026-07-18 · **Relates to:** ADR 0008 (universal labour-market OS),
`docs/audit/multilingual-answer-engine-reality-audit-v1.md`,
`docs/seo/profession-problem-search-strategy-v1.md`.

## Context
LabourMarket.ai needs a canonical, multilingual, AI/search-readable set of
labour-market answers (≥ 500 canonical questions × the fully-active locales). It
must fit the existing apex-SEO + i18n + taxonomy architecture and never become a
second CMS, a second professions/skills taxonomy, or a thin-content farm.

## Decision

### D1 — One canonical registry, content outside `messages/*.json`
The single source is `content/answer-engine/question-registry.json` (typed by
`lib/answer-engine/contract.ts`, loaded/validated by `lib/answer-engine/registry.ts`,
generated by `scripts/build-answer-registry.ts`). It stores canonical questions +
classification + per-locale status ONLY — no answer bodies in Wave 0. Kept outside
`messages/*.json` (like `lib/seo/profession-problem-content.ts`) so it has zero
i18n-debt / 11-file-parity coupling. It **references** the canonical 49 profession
+ 152 skill slugs; it defines no second taxonomy.

### D2 — URL model
`/{locale}/questions/{localized-slug}` for a single answer, `/{locale}/questions`
and `/{locale}/questions/category/{category}` for indexes. This is a NEW segment
under the existing `[locale]` tree — it does not collide with any current route
(no `/questions`, `/faq`, `/help` exists). Localized slugs are per-locale (stored
in `localizedSlugs`); the canonical slug is the stable English kebab-case id.
Rationale: no clearer canonical content route exists in the project today.

### D3 — Canonical + hreflang (reuse the apex source)
Every answer page builds metadata via `lib/seo/metadata.ts`
(`buildPageMetadata`/a new page key): `alternates.canonical` = apex
`localizedUrl(locale, path)`, `alternates.languages` = `hreflangAlternates(path)`
(one per active locale + `x-default` → the `lt` URL). Never a literal host. Each
page exports its own `generateMetadata` (avoiding the `[country]` page's
missing-metadata gap).

### D4 — Sitemap
A **questions sitemap** is added ONLY for questions whose `indexingStatusByLocale`
is `PUBLISHED`/`READY_FOR_INDEX` for that locale — built via `localizedUrl` +
`hreflangAlternates`, never literal hosts, and never for inactive locales or
incomplete pages. When volume grows, split into a **sitemap index**
(`/sitemap.xml` → child sitemaps incl. `/questions-sitemap.xml`). The questions
sitemap **must not be blocked by robots**. **Wave 0 adds nothing to the sitemap**
(no page is `READY_FOR_INDEX`).

### D5 — Structured data (JSON-LD) — allowed types only
`WebPage`, `Article`, `BreadcrumbList`, `Organization`, `DefinedTerm`, `ItemList`,
`FAQPage` (only for a real set of several editorial questions on one page), and
`QAPage` (only for a real user-answers model). **A single editorial answer must
NOT use `QAPage`.** No fake `aggregateRating`/`review`. JSON-LD is greenfield and
is added in a later wave, not Wave 0.

### D6 — Server-rendered, public, no login
Answer pages are **server-rendered** (App Router server components) and the main
answer is **publicly accessible without login** — under `(marketing)`, not behind
the `/*/dashboard|auth|onboarding` robots disallow. A short direct answer sits at
the top of the page (AI-answer friendly), followed by clear Q/A blocks, sources,
review date, breadcrumb, related questions, and a real product CTA.

### D7 — Indexing gate
A page is eligible for indexing/sitemap ONLY when its `contentStatus` is
`READY_FOR_INDEX` or `PUBLISHED` AND that locale's `indexingStatusByLocale` is
`PUBLISHED`/`READY_FOR_INDEX`. Incomplete locales are `noindex` and excluded from
the sitemap. HIGH-risk pages additionally require the high-risk gate
(`docs/policies/answer-engine-high-risk-content-v1.md`).

### D8 — AI-agent readiness
Semantic HTML; a short direct answer first; stable canonical; real
`sourceReferences`; a review date; profession/skill slug identifiers; crawlable
internal links (related questions); JSON-LD; Organization identity; citation
rules. **No public uncontrolled scrape API.** AI-crawler robots permissions are
NOT changed without an explicit owner decision (content-usage boundary).

### D9 — IndexNow / Search Console / Bing
Verification tokens live in `metadata.verification` or `public/`; the IndexNow key
is **server-only env + `public/<key>.txt`** and must never reach the client
bundle. Pings target only `READY_FOR_INDEX`/`PUBLISHED` URLs; **no mass submit**.
All owner-gated; none enabled in Wave 0.

## Consequences
- Wave 0 is doc + registry + guards only — behavior-neutral, no route, no sitemap
  or robots change, no JSON-LD, no migration.
- Later publishing waves are small and gated: (W1) route + one page template +
  server render; (W2) localized answer bodies with translation QA; (W3) JSON-LD +
  sitemap for `READY_FOR_INDEX` pages; (W4) verification + IndexNow. Each is an
  owner decision.
